MXBackspaceHold v1.4 - MX Master 4 连续退格 + 右 Ctrl 长按语音

【本版目标】
v1.4 在 v1.3 连续退格功能完全保留的基础上，新增一套“一个鼠标键完成语音输入”的交互。

核心体验：
- 按住 MX Master 4 的语音实体键：启动微信输入法长语音。
- 一直按着：正常说话，中间可以停下来思考，也可以正常滚动滚轮。
- 松开：程序自动结束微信长语音，随后自动发送。
- 如果这一次想自己检查/修改文字：按住语音键期间点一下滚轮中键，再松开；本轮只结束语音，不自动发送。


【Logi Options+ 必须这样设置】
把 MX Master 4 上用于语音的那个实体键，直接设置成：

    Keyboard Shortcut -> 右 Ctrl（Right Ctrl）

不要给这个键套 Smart Action。
不要让 Smart Action 自己录 Ctrl Down / Ctrl Up。

原因：本程序需要看到“实体右 Ctrl 的按下”和“实体右 Ctrl 的松开”，才能知道你实际按住了多久。


【为什么按住期间还能正常滚轮】
程序会吞掉 MX Master 4 发出的实体右 Ctrl。

按下时，它只向系统补发一次很短的“右 Ctrl 点按”，用来启动微信输入法的长语音模式；随后即使你手指一直按着实体鼠标键，Windows 也不会一直处于 Ctrl 按下状态。

因此：
- 滚轮旋转仍然是普通滚动；
- 不会因为 Ctrl+滚轮而把网页放大/缩小。


【语音操作】
1. 光标放到 ChatGPT / 浏览器 / 其他输入框。
2. 按住 MX Master 4 的语音键（Options+ 里映射为右 Ctrl）。
3. 微信输入法长语音启动，开始说话。
4. 中间需要思考就停，不用松开。
5. 说完直接松开。
6. 程序会：
   - 先发第 1 个 Enter：结束微信长语音并触发最后转写/排版；
   - 等待“语音自动发送延迟”；
   - 再发第 2 个 Enter：发送消息。

默认发送延迟为 800 ms。
托盘菜单可改成 500 / 800 / 1000 / 1500 / 2000 ms。
本版故意不监控微信 UI、不监控输入框文字，以保持逻辑简单稳定。


【这次不想自动发送】
在仍然按住语音键的时候：

    按一下滚轮中键（MButton）

程序会把本轮标记为“只结束，不自动发送”。
随后松开语音键时：
- 只发第 1 个 Enter，结束微信语音；
- 不发第 2 个 Enter；
- 最终文字留在输入框里给你检查、修改。

注意：
- 只有“按下滚轮中键”会作为保留标记；
- 正常上下滚动滚轮完全不受影响；
- 语音期间的这一次滚轮中键会被程序吃掉，不会同时触发浏览器中键功能。


【连续退格功能】
v1.3 的功能全部保留：
- 点一下：删除 1 个字符
- 按住：先删除 1 个字符，然后连续删除
- 松开：立即停止
- 支持 XButton1 / XButton2 切换
- 支持重复速度、长按延迟
- 支持开机自动启动
- 支持“最近检测到”侧键提示


【第一次运行】
1. 双击 Build-and-Run.cmd。
2. 它使用 Windows 自带 .NET Framework C# 编译器生成 MXBackspaceHold.exe。
3. 右下角系统托盘找到 MXBackspaceHold v1.4。
4. 确认“启用右 Ctrl 长按语音发送”已勾选。
5. 先把“语音自动发送延迟”保持为 800 ms 测试。

如果偶尔排版还没完成就触发发送：调到 1000 / 1500 ms。
如果感觉明显偏慢：试 500 ms。


【重要说明】
- 本程序会接管右 Ctrl。启用语音功能时，实体键盘上的“右 Ctrl”也会被视为语音键。
- 左 Ctrl 不受影响。
- 如果暂时需要正常使用右 Ctrl，可在托盘里取消“启用右 Ctrl 长按语音发送”。
- 普通 Chrome、微信、ChatGPT 等一般不需要管理员权限。如果目标程序以管理员身份运行，本程序也可能需要管理员权限。


v1.4 新增：
- 全局低级键盘 Hook，监听右 Ctrl 的按下/松开。
- 实体右 Ctrl 被吞掉，避免按住讲话时 Ctrl+滚轮缩放页面。
- Right Ctrl Down 时补发一次短促右 Ctrl 点按，启动微信长语音。
- Right Ctrl Up 时自动 Enter 结束语音，延迟后再 Enter 发送。
- 按住语音键期间点击滚轮中键：本轮只结束、不自动发送。
- 新增可配置语音自动发送延迟：500 / 800 / 1000 / 1500 / 2000 ms。
- 所有语音设置自动保存。
